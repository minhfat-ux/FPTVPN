# CODING RULES (RULE-CODE-*)

Baseline RULESET-0001. Source: master spec §51.

- RULE-CODE-001: Prefer proven existing abstractions over unnecessary rewrites.
- RULE-CODE-002: Do not implement custom cryptography.
- RULE-CODE-003: Keep changes scoped.
- RULE-CODE-004: Do not silently alter unrelated modules.
- RULE-CODE-005: Preserve verified backward-compatible behavior unless explicitly changed.
- RULE-CODE-006: Non-trivial changes require appropriate tests.
- RULE-CODE-007: Do not hardcode secrets.
- RULE-CODE-008: Do not fake runtime success.
